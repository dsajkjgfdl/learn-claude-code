# 概念对照

这页不是定义词典，而是用来防止你把不同层的对象混成一类。

## 最容易混的 9 组概念

| 概念 | 左边是什么 | 右边是什么 | 一句话判断 |
|---|---|---|---|
| `todo` vs `task` | 当前会话计划 | durable 工作目标 | 只对这次会话有用的是 `todo` |
| `task` vs `background task` | 要完成什么工作 | 哪个命令正在运行 | 工作目标是 `task`，执行槽位是 `background task` |
| `subagent` vs `teammate` | 一次性隔离执行 | 持续存在的团队成员 | 会结束即销毁的是 `subagent` |
| `memory` vs `context compact` | 该长期记住什么 | 如何把当前上下文压小 | 一个管“留什么”，一个管“怎么缩” |
| `permission` vs `hook` | 执行前的控制门 | 固定时机的扩展点 | 一个负责 gate，一个负责 extension |
| `message` vs `request_id` | 普通通信内容 | 结构化请求关联键 | 需要应答配对时才需要 `request_id` |
| `task` vs `worktree` | 控制平面上的工作目标 | 执行平面上的目录车道 | 任务管目标，worktree 管执行位置 |
| `plugin manifest` vs `MCP server` | 发现配置 | 外部进程 | manifest 不是 server，它只告诉系统去启动谁 |
| `MCP server` vs `MCP tool` | 能暴露多项能力的服务端 | 其中某一个具体能力项 | server 不是单个 tool，tool 只是 server 暴露出的一个入口 |

## 再补 4 个高频判断

| 看到的东西 | 先问自己什么 |
|---|---|
| 新 manager | 它到底在持有什么状态 |
| 新 tool | 它把哪种能力接进了同一条主循环 |
| 新文件落盘 | 这是 durable state 还是 runtime trace |
| 新“自动化”逻辑 | 它是在主循环里，还是在主循环旁边 |

## 记忆口诀

- 计划不等于任务
- 任务不等于执行
- 隔离不等于团队
- 压缩不等于记忆
- 目录不等于目标
