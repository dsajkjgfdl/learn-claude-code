# Agents 课程总图

这套 `agents/` 课程不是 19 个互不相干的小功能，而是一条不断长大的 agent 主线。

## 这套课到底在长什么

- 从 `s01` 开始，先把最小可工作的 `agent_loop` 立住。
- 从 `s02-s06` 开始，给这条主线补工具、计划、上下文隔离、技能和压缩。
- 从 `s07-s11` 开始，控制面开始变厚：权限、hooks、memory、prompt 组装、恢复机制。
- 从 `s12-s14` 开始，系统第一次长出“会话外状态”和“运行时执行槽位”。
- 从 `s15-s19` 开始，边界升级到平台层：团队、协议、自主性、worktree、MCP。

## 四个阶段

| 阶段 | 章节 | 真正在学什么 |
|---|---|---|
| 单 agent 主骨架 | `s01-s06` | 一条 agent 主循环如何成立 |
| 控制面 | `s07-s11` | 意图如何被约束、扩展、记忆和恢复 |
| 会话外状态 | `s12-s14` | durable task、runtime task、schedule 如何进入系统 |
| 平台边界 | `s15-s19` | 多 agent、协议、隔离车道、外部能力如何并入同一控制面 |

## 全程最重要的主线

1. 用户输入进入 `messages`
2. 模型返回文本或 `tool_use`
3. 工具执行得到真实结果
4. `tool_result` 回流到同一条主循环
5. 显式状态逐章变多，但主循环主干尽量不乱

## 你真正要背下来的边界

- `todo` 是当前会话计划，不是 durable task
- `task` 是工作目标，不是后台执行槽位
- `background task` 是运行中的命令，不是任务板
- `subagent` 是一次性上下文隔离，不是长期 teammate
- `memory` 是跨会话信息，不是更长的上下文窗口
- `worktree` 是执行车道，不是任务本身

## 看代码时固定顺序

1. 先看状态结构或 manager
2. 再看工具列表和 handler
3. 再看 `agent_loop()` 或主推进函数
4. 最后再看 CLI 入口

## `s_full.py` 的位置

`s_full.py` 不是第一站。它更像总装视角，适合在你已经知道各章边界以后，再回来看整合后的驾驶舱。

## 一句话记忆

这套课讲的不是“agent 功能清单”，而是“同一条 agent 主循环如何一步步长成平台”。
