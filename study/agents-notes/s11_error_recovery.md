# s11 Error Recovery

## 这章解决什么问题

让 agent 出错时优先恢复继续工作，而不是直接崩掉。

## 新增的核心状态

- 截断恢复计数
- prompt 过长后的 compact 重试状态
- transport error 的 backoff 重试状态

## 新增的工具/接口

- 没有新增用户工具
- 新增的是围绕模型调用的恢复分支

## 接到主循环哪里

- 模型返回后先检查 `stop_reason`
- API 出错时根据错误类型决定继续、压缩或退避重试

## 和前面章节的边界

- 这章不是新增能力
- 这章是在保证已有能力掉坑后还能接着走

## 最小时序

1. 发起模型调用
2. 检查是否截断或报错
3. 选择 continuation / compact / backoff
4. 再试一次当前回合

## 自己重写时最小要保留什么

- 输出截断恢复
- prompt 过长后的 compact 重试
- 临时网络错误的指数退避

## 一句话记忆

健壮 agent 的关键不是“不出错”，而是“出错以后还能接着推进”。
